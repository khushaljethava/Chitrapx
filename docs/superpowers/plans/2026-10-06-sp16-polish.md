# Sub-project 16: Polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:**
- A "new version available" banner.
- A static changelog.
- Consent-gated, first-party, cookieless analytics with a report-only CSP.
- A community template feed with publish, import, report and staff moderation.
- The 16.5 and SP9 leftovers.

**Spec:** `docs/superpowers/specs/2026-10-06-sp16-polish-design.md` (acceptance criteria: `docs/roadmap/sp16-polish.md`).

**Tech stack:** Next.js 16 (read `apps/web/node_modules/next/dist/docs/` before touching Next APIs), React 19, Zustand + Immer, Drizzle + Postgres, Vitest.

## Global constraints

- Billing is Razorpay only. SP16 charges nothing and touches no prices.
- SP13 and SP14 are dropped.
- No document `schemaVersion` bump. Every editor change is one `apply(command)`.
- **One migration, `0013_*`**, generated with `pnpm --filter @chitrapx/db generate` and then hand-edited for RLS. It is **not** run against the shared database. DB tests that need its tables run against a throwaway local Supabase Postgres:

  ```bash
  docker run -d --name sp16-pg -e POSTGRES_PASSWORD=postgres -p 127.0.0.1:55416:5432 public.ecr.aws/supabase/postgres:17.11.0.002
  (cd packages/db && DATABASE_URL=postgres://postgres:postgres@127.0.0.1:55416/postgres npx drizzle-kit migrate)
  DATABASE_URL=postgres://postgres:postgres@127.0.0.1:55416/postgres pnpm --filter @chitrapx/web exec vitest run test/community.test.ts
  ```

- DB tests run with `--testTimeout=90000 --hookTimeout=90000`.
- No dev server, MinIO or e2e runs. E2E specs may be written but are not run.
- Files another branch is editing are not touched: `editor/shortcuts.ts`, `server/uploads.ts`, `server/ai.ts`, `server/jobs.ts`, `server/apps.ts`, `worker/src/bundle.ts`, `worker/src/ai/jobs.ts`, the `document` ai/translations files, and `ChipsEditor.tsx`.

### Task 8: Consent, track, events route, CSP, privacy (16.3)
- `lib/consent.ts`:
  - `CONSENT_VERSION`, `CONSENT_COOKIE`;
  - `parseConsent(cookieHeader, version)`;
  - `consentCookie(choice, version)`;
  - `privacySignal(nav)`;
  - `effectiveConsent(cookie, nav, version)`, which returns `granted`, `denied` or `ask`.
- `lib/analyticsEvents.ts`: `EVENTS`, `normalizePath` and `cleanEvent(raw)`, which returns `{ name, path, props }` or null.
- `lib/track.ts`: `setTrackingEnabled` and `track(name, props?)`, which uses `sendBeacon` to `/api/events` only when enabled and the event is allowed.
- `app/api/events/route.ts`: a 1 KB body limit, then `cleanEvent`, then an insert into `analytics_events`. It returns 204, and 204 with nothing stored when analytics is off.
- `components/AnalyticsConsent.tsx`: the banner, the page-view effect, and the `chitrapx:cookie-settings` event listener. `components/CookieSettingsLink.tsx`. Footer links go on the landing page and the dashboard layout.
- `auth/callback`: `?welcome=1` when a workspace is created.
- Track calls go at the call sites: `TemplateGallery`, `ExportDialog`, and the community share and import.
- `lib/csp.ts`: `cspHeader({ supabaseUrl, storageEndpoint, dev })`. `proxy.ts` sets the report-only header.
- `app/privacy/page.tsx`.
- `.env.example`: `NEXT_PUBLIC_ANALYTICS`, `BUILD_ID`, `STAFF_EMAILS`.
- Tests:
  - `consent.test.ts`: the version bump asks again; DNT and GPC deny; garbage cookies are ignored.
  - `analyticsEvents.test.ts`: unknown events and props are dropped; emails, UUIDs and query strings never survive; paths are normalised.
  - `track.test.ts`: nothing is sent before consent or after revoke.
  - `csp.test.ts`: there is no third-party script host other than Razorpay, and the S3 and Supabase origins are present.
  - `events.test.ts` (local DB): the route stores a cleaned row and refuses a large body.
